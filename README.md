# Learnova (ليرنوفا) 🧠✨

**Learnova** هي منصة ذكية، تفاعلية، ومتكاملة صُممت خصيصاً لدعم الأطفال ذوي طيف التوحد (Autism)، بالإضافة إلى توفير بيئة متقدمة لأولياء الأمور والأطباء لمتابعة حالة وتطور الطفل. يجمع التطبيق بين الألعاب التعليمية التفاعلية، أدوات التواصل البديل (PECS)، إدارة الروتين اليومي، وتقنيات الذكاء الاصطناعي (AI) لتقديم تجربة علاجية وتعليمية مخصصة وممتعة في مكان واحد.

## 🎯 نبذة عن المشروع | About

**Learnova** نظام ثلاثي الأبعاد يخدم ثلاث فئات رئيسية بتجارب (UX) منفصلة تماماً لكل فئة:

1. **بوابة الطفل (Child Portal):** 
   - واجهة بصرية خالية من المشتتات والضوضاء البصرية، تعتمد على الأنيميشن السلس والألوان المريحة.
   - تهدف إلى تعزيز المهارات الإدراكية، الحركية، اللغوية، والاجتماعية للطفل بدون أي شعور بالضغط النفسي.
   - تحتوي على ألعاب تعليمية، نظام تواصل بالصور (PECS)، وروتين يومي تفاعلي بمكافآت (Gamification).

2. **بوابة ولي الأمر (Parent Dashboard):** 
   - لوحة تحكم إحصائية شاملة تعرض تقارير تقدم الطفل (النقاط، الألعاب الأكثر استخداماً، تحليل المشاعر اليومية).
   - توفر نظام دردشة مع مساعد ذكي متخصص (AI Assistant) لتقديم استشارات فورية ومقترحات للتعامل مع نوبات الغضب أو تطوير المهارات.

3. **بوابة الطبيب (Doctor Dashboard):** 
   - نظام إدارة عيادات (Clinic Management) يسمح للطبيب بإضافة ملفات المرضى، متابعة أداء الأطفال الذين يشرف عليهم.
   - تحليل متقدم للبيانات (Data Analytics) يساعد الطبيب في بناء خطط علاجية (Treatment Plans) وتعديلها بناءً على التفاعل الحقيقي للطفل داخل التطبيق.

## 💻 التقنيات المستخدمة | Tech Stack

تم بناء المشروع بالاعتماد على أحدث حزم الـ Frontend وتطوير الويب الحديث:

- **إطار العمل (Framework):** `React 19` مدعوماً بـ `Vite` لتسريع بيئة التطوير (HMR) وعملية الـ Build.
- **التصميم وتنسيق الواجهات (Styling):** `Tailwind CSS v4` مع استخدام الـ Design Tokens ومسار ألوان OKLCH لدقة بصرية عالية.
- **مكتبات الـ UI الجاهزة:** `@heroui/react` لتوفير مكونات (Buttons, Modals, Inputs) متجاوبة وتدعم الـ Accessibility.
- **الأنيميشن والحركة (Motion):** `framer-motion` وهو العصب الأساسي لحركة المشروع بالكامل (Scroll effects, Spring physics, Page Transitions).
- **قواعد البيانات والتوثيق (Backend & Auth):** `Firebase` (يتم استخدام `Firestore` لتخزين البيانات و `Firebase Auth` للمصادقة وإدارة الحسابات).
- **التوجيه (Routing):** `react-router-dom v7`.
- **الذكاء الاصطناعي (AI):** `Google Gemini AI API` (يستخدم لتوليد المحادثات وتحليل المشاعر وتكوين توصيات مخصصة).
- **الخرائط (Maps):** `react-leaflet` مع `leaflet` لعرض العيادات المتاحة لولي الأمر (Clinics Map).
- **الرسوم البيانية (Charts):** `recharts` لعرض تقدم الطفل ونقاطه في لوحات التحكم (Dashboards).

## 🏗️ المعمارية وقواعد التنظيم | Architecture Rules

المشروع يتبع معمارية **Feature-Based Architecture (معمارية الميزات)** وهو نمط متقدم في هندسة البرمجيات (Senior Level Pattern) يضمن التوسع (Scalability) وسهولة الصيانة:

1. **التقسيم حسب الميزة (Flat Feature Folders):** 
   بدلاً من تنظيم المشروع حسب نوع الملفات (components, pages, styles)، يتم تنظيم المشروع حول "الميزة" نفسها. كل ميزة (مثل الألعاب، لوحة التحكم) تعيش داخل مجلد مستقل في `src/features/{feature-name}/`.

2. **نمط الـ Orchestrator (الملف المنسق):**
   داخل كل ميزة، لا نستخدم مجلدات `pages/`. بدلاً من ذلك، يوجد ملف رئيسي واحد يحمل اسم الميزة (مثلاً `GamesHub.jsx`). هذا الملف هو الـ Orchestrator الذي:
   - يتصل بالـ Contexts (مثل Auth أو GlobalData).
   - يجلب البيانات من الـ Server/API.
   - يمرر هذه البيانات كـ Props للمكونات الفرعية.
   - **القاعدة الذهبية:** هذا الملف لا يجب أن يحتوي على كود UI ضخم، بل يعتمد على مكونات صغيرة.

3. **المكونات الفرعية (Components Scope):**
   كل ميزة تحتوي على مجلد `components/` خاص بها. هذه المكونات (مثل `GamesHubHeader.jsx` أو `GameCard.jsx`) غير مسموح لها بالتواصل المباشر مع قاعدة البيانات لتظل (Pure & Reusable).

4. **فصل المنطق عن الواجهة (Server Separation):**
   أي دوال مسؤولة عن جلب أو رفع بيانات معقدة يتم فصلها في مجلد `server/` بداخل الميزة (مثل `artStudioServer.js`) لتنظيف المكونات من المنطق البرمجي (Business Logic).

## 📄 الصفحات وأهميتها وميكانيكية عملها | Pages & Importance

1. **الصفحة الترحيبية (Landing):**
   - **الأهمية:** واجهة المشروع للعالم. تعتمد بكثافة على تأثيرات `framer-motion` لعرض الميزات بشكل قصصي (Storytelling) بتقنية (Scroll Sequences).
   
2. **اختيار الدور (Choice Page):**
   - **الميكانيكية:** تتيح للمستخدم تحديد دوره (طبيب، ولي أمر، طفل) وبناءً عليه يتم توجيهه لنوع تسجيل الدخول المناسب. البيانات والنصوص تُسحب ديناميكياً.

3. **تسجيل الدخول والمصادقة (Auth - Child, Parent, Doctor):**
   - **الأهمية:** لكل نوع حساب متطلبات مختلفة. (الطفل يحتاج واجهة بسيطة ومبنية على شخصيات كرتونية، الطبيب يحتاج واجهة رسمية، والأب يحتاج واجهة سهلة للاستخدام). 

4. **الرئيسية للطفل (Child Home):**
   - **الميكانيكية:** بيئة مسارات فضائية/كرتونية. يتم إنشاء المسارات ديناميكياً من بيانات Firebase وتوجه الطفل للأقسام (ألعاب، روتين، مشاعر) مع مؤثرات (Hover Glow).

5. **منظومة الألعاب (Games Hub):**
   - **Word Builder:** لعبة تعليمية (Drag & Drop Logic أو النقر) لترتيب الحروف الإنجليزية لتكوين كلمات معتمدة على صور مع نطق صوتي.
   - **Puzzle:** تعمل بخوارزمية تقطيع الصور إلى شبكة (Grid) ومتابعة موقع القطع (Coordinates) لمعرفة حالة الفوز.
   - **Art Studio:** يعتمد على الـ `HTML Canvas API` لتسجيل إحداثيات رسم الطفل (Stroke Paths)، مع أدوات تلوين، ومسح، وحفظ الرسم كصورة (DataURL).
   - **Piano:** يعتمد على تشغيل أصوات (Audio Objects) مبرمجة على النوتات مع تأثيرات حركية عند الضغط.

6. **لوحات التحكم (Dashboards):**
   - **Parent Dashboard:** تستخدم `recharts` لرسم بيانات تقدم الطفل. تجلب نقاط الطفل من الـ Database وتدير الجلسات مع مساعد الـ AI.
   - **Doctor Dashboard:** تعرض جدول (Table) للمرضى مع ميزة الفلترة والبحث، وتحليل بيانات الحالات للوصول إلى أنماط سلوكية بمساعدة الـ AI.

7. **التواصل والمشاعر (PECS & Emotions):**
   - **PECS:** نظام بناء الجُمل الصورية. يختار الطفل صوراً (مثلاً: "أنا أريد" + "تفاحة") ويقوم التطبيق بتجميعها ونطقها باستخدام `Web Speech API`.
   - **Emotions:** اختيار الوجه التعبيري الذي يمثل شعور الطفل اليوم، وتسجيل هذا الشعور في قاعدة البيانات ليعرفه الطبيب وولي الأمر.

8. **الاسترخاء (Calming Area):**
   - **الميكانيكية:** تطبيق تقنيات التنفس العميق (4-7-8 Breathing Technique) بصرياً عبر دائرة تتسع وتضيق (Scaling Animation) لتهدئة نوبات الهلع (Meltdowns).

## 🧩 المكونات المشتركة في التفاصيل | Shared Components

في المجلد `src/shared/components/`:
- **`MainNavbar.jsx`:** شريط علوي يكتشف حالة الـ Route الحالي. إذا كان المستخدم في منطقة الطفل، يصبح شكله مرحاً، وإذا كان للطبيب يصبح احترافياً (أزرق/رصاصي). يتعامل مع تسجيل الخروج وتغيير اللغات.
- **`SharedAuthForm.jsx`:** استمارة تسجيل موحدة تقبل Props تحدد نوع المستخدم، وتقوم بإدارة أخطاء Firebase بشكل مركزي وعرض إشعارات (Toasts).
- **`AutismSupportBot.jsx`:** روبوت عائم (Floating Widget) متاح لأولياء الأمور لاستشارة الـ AI في أي وقت، مع احتفاظه بسياق المحادثة (Chat History).
- **`ClinicsMap.jsx`:** خريطة تفاعلية مدعومة بـ Leaflet لعرض أقرب عيادات ومراكز التأهيل المتوفرة في المنطقة.

## 🗄️ إدارة الحالة | State Management

التعقيد الكبير في النظام تطلب إدارة حالة متقدمة (Advanced State Management) مقسمة كالتالي عبر الـ `React Context API`:

1. **`AppContext` (Theme & i18n):**
   - مسؤول عن قراءة وكتابة (Dark/Light mode) لـ `localStorage`، وتعديل الكلاس `dark` على مستوى الـ HTML root.
   - مسؤول عن اللغة (`isArabic`). يقوم بتبديل اتجاه الصفحة (`dir="rtl" / "ltr"`) تلقائياً ويوفر دالة الترجمة.

2. **`AuthContext` (User Session & Role):**
   - يستمع لتغيرات المصادقة عبر `onAuthStateChanged` الخاص بـ Firebase.
   - عند تسجيل الدخول، يجلب الـ `Document` الخاص بالمستخدم لمعرفة الـ `Role` (طبيب، أب، طفل) وإرفاق البيانات في State واحدة تسمى `user` متوفرة في جميع أنحاء التطبيق.

3. **`GlobalDataContext` (Firebase Static Config):**
   - **أهم تحديث هندسي في المشروع:** بدلاً من وضع القوائم، النصوص، والبيانات كـ "Hardcoded Arrays" داخل ملفات React، يتم سحب مستند مركزي (`system/appData`) من Firestore مرة واحدة عند بدء التطبيق.
   - يوفر `appData` للواجهات (أزرار الاختيار، بيانات الأقسام، ألوان شاشات الـ Auth) لتصبح المنصة Dynamic بالكامل 100%.

4. **`DataContext` (Progress & Routines):**
   - مسؤول عن النقاط المكتسبة من الألعاب (Points).
   - مسؤول عن المهام اليومية للطفل (Routine checkboxes) ومزامنة إنجازها مع قاعدة البيانات لحظياً.

## 🌐 البيانات | Data Layer (Firebase)

- **Firebase Firestore** هو القلب النابض للبيانات (Single Source of Truth).
- **هيكلة الـ Collections الأساسية:**
  - `users/`: يحتوي على ملفات المستخدمين وتحديد صلاحياتهم (Role).
  - `system/appData`: يحتوي على الهيكلة التكوينية (Configuration) للألعاب والـ UI.
  - `child_progress/`: يسجل عدد مرات الفوز في البازل، تكوين الكلمات، والمشاعر اليومية.
  - `conversations/`: يحفظ سجلات محادثات الذكاء الاصطناعي للمراجعة والتحليل.

## 🤖 الذكاء الاصطناعي | AI Integration

تم تصميم المعالجة اللغوية بدمج واجهة **Google Gemini API** مع تخصيص الـ (System Prompts) بشدة:

1. **المساعد الذكي لولي الأمر (Parent Companion):** 
   يتم حقن النظام بتعليمات (Prompts) تخبر الذكاء الاصطناعي بـ: *"أنت استشاري تربوي متخصص في التوحد. أجب بأسلوب متعاطف وعلمي."* مما يعطي ردوداً احترافية وداعمة لولي الأمر.
2. **المساعد الطبي (Doctor Analytics AI):** 
   يقرأ بيانات الطفل (معدل الغضب، درجات الألعاب) ويحللها ليولد تقريراً أو مقترحاً طبياً لتعديل الجرعات أو خطط السلوك.
3. **رفيق الطفل (Child AI Bot):** 
   يتم تقييد الإجابات (Constraint Prompts) لتكون جمل قصيرة جداً، إيجابية، وبسيطة (أقل من 15 كلمة) مع إضافة رموز تعبيرية (Emojis) ليتفاعل معها الطفل بأمان.

## 🔐 نظام الـ Routing والتوثيق | Routing & Auth

- تم التنفيذ باستخدام `react-router-dom`.
- يعتمد الأمان على مكون **`<ProtectedRoute />`**:
  - يتفقد المكون إذا كان المستخدم مسجلاً (Authenticated).
  - يتفقد إذا كان دور المستخدم (Role) يتطابق مع المسار المطلوب (مثلاً `/doctor-dashboard` متاح فقط لمن يحمل `role === 'doctor'`).
  - في حال المخالفة، يتم توجيهه إلى `/choice` أو صفحته الرئيسية.
- يمنع الطفل من الخروج أو تسجيل الخروج بالخطأ إلا عبر واجهات مخصصة، لحمايته أثناء استخدام الأجهزة اللوحية.

## 🎨 التصميم الفني والبصري | Design System

- **الأنيميشن (Animation First Approach):** 
  لم يتم إضافة الأنيميشن كـ (إضافة أخيرة)، بل بُنيت الواجهات حول الحركة. تأثيرات (Hover-Lift)، وتأثيرات (Page Reveal) بُرمجت بدقة عبر (Spring Physics) المتاحة في `framer-motion` لضمان إحساس طبيعي بالجاذبية والسلاسة.
- **Glassmorphism & Glow:** 
  استخدام مكثف للفلاتر (`backdrop-blur`) والخلفيات شبه الشفافة (`bg-white/10`) والحدود المضيئة لإعطاء طابع مستقبلي (Premium Cinematic Look).
- **متغيرات الألوان (Color Tokens):** 
  استخدام مسار الألوان المعياري (OKLCH) بدلاً من HEX التقليدي لضمان أن التدرجات اللونية (Gradients) تندمج بسلاسة دون تشوهات (Color Banding) خاصة في الوضع الليلي.
- **الخطوط (Typography):** 
  الاعتماد على خطوط احترافية لجوجل (Google Fonts):
  - `Inter`: لنصوص القراءة والمحتوى.
  - `Space Grotesk`: للعناوين الجريئة والشعارات.
  - `JetBrains Mono`: للتفاصيل التقنية والنقاط والأرقام.

3. **متغيرات البيئة (Environment Variables):**
   يجب إنشاء ملف `.env` في المسار الرئيسي (Root) وتضمين المفاتيح التالية للذكاء الاصطناعي و Firebase:
   ```env
   VITE_GEMINI_API_KEY=your_gemini_key_here
   VITE_FIREBASE_API_KEY=your_firebase_api_key
   VITE_FIREBASE_AUTH_DOMAIN=your_domain.firebaseapp.com
   VITE_FIREBASE_PROJECT_ID=your_project_id
   VITE_FIREBASE_STORAGE_BUCKET=your_storage_bucket
   VITE_FIREBASE_MESSAGING_SENDER_ID=your_sender_id
   VITE_FIREBASE_APP_ID=your_app_id
   ```
4. **تشغيل بيئة التطوير (Development Server):**
   ```bash
   npm run dev
   ```
5. **البناء للإطلاق (Production Build):**
   ```bash
   npm run build
   ```
